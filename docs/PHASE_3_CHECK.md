# Phase 3 verification

- The adapter uses `POST /chat/completions` with `model`, `messages`, and `stream: false`, and reads `choices[0].message.content`. It accepts either a base URL or a full completion URL. [OpenAI's Chat Completions reference](https://platform.openai.com/docs/api-reference/chat/create) describes that contract. Endpoint URLs must use HTTPS except loopback HTTP; URL credentials, queries, and fragments are rejected.
- Model IDs, selected model, endpoint, and encrypted key material persist in a separate browser storage record. PBKDF2-SHA-256 (310,000 iterations) derives an AES-GCM 256 key from a passphrase and a random salt; each encryption uses a fresh IV. The key is decrypted into tab memory on unlock. The user can lock or remove it. No key enters workspace snapshots, model request context, or application error text.
- Topic creation offers a complete generated Markdown article with headings. The draft and answer remain typed, persisted proposals until accepted. The before/after preview allows editing; acceptance records proposal and model origin, increments article revision, and uses the existing undo/redo history. Stale article edits fail rather than overwriting intervening work. Rejected or merely viewed output does not alter the article.
- Ask uses an article excerpt (up to 6,000 characters), exact selected text, or a node's title and Markdown. Imported source files are not sent. The request UI exposes the context and configured endpoint; the result is labeled as unverified. Model-generated links and numeric citation markers are removed rather than shown as verified source citations. The saved AI history exposes request, model, status, and proposal content.
- `npm test` passes all 17 tests including encryption/unlock, default active-model selection, transport validation, request payload, response/error handling, incomplete generation, and non-mutating preview. `npm run build` passes. The running app on port 4173 saved an OpenRouter completion URL, one model, and an encrypted key. Two repeated saves in the same settings dialog preserved the encrypted key. A reload preserved the settings and locked the key; the passphrase unlocked it again.
- A live request to OpenRouter using `openai/gpt-5.6-luna` generated a complete Lean article. The proposed outline and article were reviewed before acceptance, then the canvas displayed the accepted article with its AI origin. A second live Ask request explained why `rfl` proves `2 + 2 = 4`. Its answer remained a proposal until preview and acceptance. Undo removed its new section; redo restored it. Reload reopened the accepted article and both proposal records.

Limits: this browser prototype cannot keep a usable API key secret from a malicious same-origin script or browser extension while the key is unlocked. Direct remote calls require provider CORS support. Model output is not a verified external source. The phrase insertion uses an exact Markdown match and otherwise appends a new section; users should review the editable before/after preview carefully.
